= Model Serving with Red Hat AI Inference

== Welcome to Model Serving with Red Hat AI Inference


Let's talk about the reality of serving Large Language Models (LLMs) in the enterprise.

Under the hood, these models are performing incredibly complex, computationally heavy tasks. But for those of us on the infrastructure and platform teams, deploying and managing them shouldn't require a Ph.D. in hardware engineering. We need to focus on delivering business ROI—cost-effective token generation, strict SLOs, and secure endpoints—not spending our weeks debugging CUDA drivers and infrastructure maintenance.

That is exactly the problem Red Hat AI Inference (RHAII) solves. By packaging the highly performant vLLM serving engine into a hardened, supported container, RHAII allows us to transform the chaotic process of AI deployment into a predictable, manageable system.

**Evolution of Red Hat AI Inference 3.4**

If you've been around the Red Hat ecosystem, you might notice a name change. Red Hat AI Inference Server (RHAIIS) has officially been rebranded to Red Hat AI Inference (RHAII).  This change reflects a massive leap in capability. With version 3.4, RHAII introduces Distributed Inference using the Kubernetes-native llm-d framework and Gateway API routing. This allows organizations to build centralized, multi-node Models-as-a-Service (MaaS) platforms on OpenShift.

However, we are keeping things grounded. Before you can run a massive, distributed cluster, you have to master the engine. This course focuses entirely on the core mechanics of single-node, single-GPU deployments on RHEL. The complexities of llm-d operations are out of scope for today and will be covered in a dedicated advanced course.

=== Clearing the GPU vRAM

Because GPU memory is a strictly finite resource, two LLMs cannot easily share the same GPU in this configuration. Your lab environment has a small AI service running in the background automatically.  Before we can take control of the server for our own deployments, we must stop the pre-configured service to free up the GPU's memory.  Once your lab is booted, run the following command in your terminal:


[source,bash]
----
sudo systemctl stop rhaiis.service
----
